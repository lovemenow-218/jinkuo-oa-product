**需求描述**

**工作交接 · 入口与显示范围（web）**

web 左侧菜单「人事」下新增「工作交接」菜单，与员工档案、考勤记录、工资表并列；

显示范围与 h5 一致，仅 qt 品牌测试门店可见；本期不做权限点控制。

**工作交接页 · 页面结构（web）**

点击「人事」→「工作交接」进入列表页，面包屑「人事 / 工作交接」，页标题「工作交接」；

三个页签：在途任务转交、流程节点处理人、转交记录，默认显示「在途任务转交」，切页签保留各自的勾选状态；

三个页签均无查询区，进入即按当前登录用户列出本人名下数据，不提供查询他人的入口；

列表分页沿用 web 端既有列表分页样式；各页签需覆盖空状态、加载中、错误态：在途任务转交空态提示「暂无待处理的审批任务」；流程节点处理人空态提示「暂无由你负责的流程节点」；转交记录空态提示「暂无转交记录」。

**工作交接页 · 页签一 在途任务转交**

列表按发起时间倒序展示本人名下在途审批任务，表格列：勾选框、审批编号、审批模板、标题、发起人、发起时间、当前节点；

勾选交互：点表头勾选框对本页全选 / 取消全选，已选数量显示在列表下方操作条「已选 n 项」；翻页不保留跨页勾选；

列表下方操作条右侧「批量转交」按钮：已选为 0 时置灰不可点；提交中置灰显示「转交中…」避免重复提交；

点击「批量转交」弹出「批量转交 · 选择接手人」弹窗：顶部搜索框按姓名过滤，候选列表逐行显示姓名、岗位，单选；

接手人规则：在职、与本人同属一个门店、不可与本人相同；不满足条件的候选人不出现，重名候选人靠岗位区分；

弹窗底部「取消」「确认转交」按钮；未选人时「确认转交」置灰；

确认后关闭弹窗、刷新列表、toast「转交成功」；转交后任务从本人待办中移除，进入接手人的待办，后续由接手人正常审批；

只转交本人名下的在途任务，不支持转交他人任务；已完成、已驳回的审批单不在范围。

**工作交接页 · 页签二 流程节点处理人**

进入页签即按当前登录用户列出本人作为指定处理人的审批流程模板及节点：按流程模板分组，组头显示流程模板名称，表格列：勾选框、节点名称、节点类型、当前处理人；

只展示节点类型为「指定成员」且当前处理人是本人的节点；角色、主管、表单控件关联等动态类型节点不在列表中，这类节点按流程配置自动取人，无需替换；

勾选多个节点后，列表下方操作条「已选 n 项」+「批量替换处理人」按钮：已选为 0 时置灰；提交中置灰显示「替换中…」防重复提交；

点击「批量替换处理人」弹出「批量替换 · 选择新处理人」弹窗，交互与「选择接手人」弹窗一致：搜索、候选列表显示姓名与岗位、单选、未选人确认按钮置灰；新处理人须为在职、与本人同属一个门店、不可与本人相同；

确认后关闭弹窗、刷新列表、toast「替换成功」；替换只对之后新发起的单据生效，已发起的在途单据不受影响，仍按「在途任务转交」处理；

系统记录每次替换的流程模板、节点、原处理人、新处理人、操作人、操作时间，写入「转交记录」页签；操作人为发起替换的员工本人。

**工作交接页 · 页签三 转交记录**

按时间倒序展示两类操作的记录，表格列：操作类型（在途任务转交 / 流程节点替换）、摘要信息（转交显示移交人与接手人，替换显示流程模板与节点）、操作人、操作时间、操作（查看）；

点「查看」弹出记录详情弹窗：在途任务转交详情含移交人、接手人、任务清单（逐条列审批编号与标题）、操作人、操作时间；流程节点替换详情含流程模板、节点、原处理人、新处理人、操作人、操作时间；

记录只读，不可编辑、不可删除；操作人即发起该次操作的员工本人。

**工作交接 · 转交通知（web）**

在途任务转交成功后，接手人收到一条任务转交通知，文案含移交人、转交任务数量，点击跳转到 web「待我处理」列表；

流程节点处理人替换成功后，新处理人收到一条处理人变更通知，文案含流程模板名称、节点名称、原处理人，点击跳转到发起审批页；

通知复用消息中心既有卡片样式与类型图标规则，时间格式为 yyyy-MM-dd HH:mm。

**待确认**

流程节点处理人替换目前为勾选多条后统一替换为同一人；一人多岗时（如同时有人事类、出纳类流程），不同流程可能应换给不同的接手人，是否改为逐条节点单独选择新处理人，待评审确认。

**附：已知说明**

本期仅 qt 品牌测试门店开放，按门店写死控制，不做权限点控制；后续全量开放需补权限点与门店配置；

工作交接含在途任务批量转交、流程节点处理人替换两项，均由员工本人发起、只处理本人名下的任务与节点；权限点移交归入离职交接，工作交接不处理权限点；

工作交接保持简单、不按交接内容分项选人；本人兼多岗时分多次操作，每次勾对应任务转给对应接手人；

历史单据与已生成预警记录保留原责任人，不随交接改写；预警接收人只改在途单据，历史记录不动；

交接双方限同一门店内，不做跨门店交接，不额外设层级限制；

h5 与 web 两端工作交接的数据与记录互通，任一端发起的操作在两端均可查看。
