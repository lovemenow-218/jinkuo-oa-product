**需求描述**

**工作交接 · 入口与显示范围（h5）**

h5 工作台「人事」分组新增「工作交接」图标入口，与员工档案等并列；

点击进入工作交接页，仅 qt 品牌测试门店显示该入口，通过代码按门店写死控制，其他门店不显示；

本期不做权限点控制，入口只按门店显示，不做角色授权。

**工作交接页 · 页面结构（h5）**

从工作台进入后，顶部页标题「工作交接」，下方三个页签：在途任务转交、流程节点处理人、转交记录，默认显示「在途任务转交」；

切页签保留各自的勾选状态与浏览位置；三个页签均无查询区，进入即按当前登录用户列出本人名下数据，不提供查询他人的入口；

列表上拉加载更多，沿用 h5 既有列表加载样式；各页签需覆盖空状态、加载中、错误态：在途任务转交空态提示「暂无待处理的审批任务」；流程节点处理人空态提示「暂无由你负责的流程节点」；转交记录空态提示「暂无转交记录」。

**工作交接页 · 页签一 在途任务转交**

列表按发起时间倒序展示本人名下在途审批任务，每条显示审批编号、审批模板、标题、发起人、发起时间、当前节点，左侧带勾选框；

勾选交互：点勾选框或整条卡片切换选中态，已选数量实时显示在底部按钮文案中；不做全选（在途任务数量少且涉及不同流程，全选易误转）；

列表底部固定「批量转交（n）」按钮：n 为 0 时按钮置灰不可点；提交中按钮置灰显示「转交中…」，避免重复提交；

点击「批量转交」进入「选择接手人」页：顶部标题「选择接手人」，副标题显示已选任务数量；下方为候选人列表，逐行显示姓名、岗位，按姓名拼音排序，支持按姓名搜索过滤；

接手人规则：在职、与本人同属一个门店、不可与本人相同；不满足条件的候选人不出现，重名候选人靠岗位区分；

点选候选人后底部「确认转交」按钮亮起，点击执行转交；未选人时按钮置灰；

转交成功返回工作交接页并 toast「转交成功」；转交后任务从本人待办中移除，进入接手人的待办，后续由接手人正常审批；

只转交本人名下的在途任务，不支持转交他人任务；已完成、已驳回的审批单不在范围。

**工作交接页 · 页签二 流程节点处理人**

进入页签即按当前登录用户列出本人作为指定处理人的审批流程模板及节点：按流程模板分组，组头显示流程模板名称，组内逐行列出节点名称、节点类型、当前处理人，每行带勾选框；

只展示节点类型为「指定成员」且当前处理人是本人的节点；角色、主管、表单控件关联等动态类型节点不在列表中，这类节点按流程配置自动取人，无需替换；

每行可点进节点详情页，详情显示流程模板、节点名称、节点类型、当前处理人，并提供「替换该节点处理人」入口，走与批量相同的选人流程（单选一条）；

勾选多个模板节点后，底部固定「替换处理人（n）」按钮：n 为 0 时置灰；提交中置灰显示「替换中…」防重复提交；

点击「替换处理人」进入「选择新处理人」页，交互与「选择接手人」页一致：候选列表显示姓名、岗位，支持按姓名搜索；新处理人须为在职、与本人同属一个门店、不可与本人相同；

替换成功返回并 toast「替换成功」；替换只对之后新发起的单据生效，已发起的在途单据不受影响，仍按「在途任务转交」处理；

系统记录每次替换的流程模板、节点、原处理人、新处理人、操作人、操作时间，写入「转交记录」页签；操作人为发起替换的员工本人。

**工作交接页 · 页签三 转交记录**

按时间倒序展示两类操作的记录，每条显示操作类型（在途任务转交 / 流程节点替换）、摘要信息（转交显示移交人与接手人，替换显示流程模板与节点）、操作时间；

点开记录进详情页：在途任务转交详情含移交人、接手人、任务清单（逐条列审批编号与标题）、操作人、操作时间；流程节点替换详情含流程模板、节点、原处理人、新处理人、操作人、操作时间；

记录只读，不可编辑、不可删除；操作人即发起该次操作的员工本人。

**工作交接 · 转交通知（h5）**

在途任务转交成功后，接手人收到一条任务转交通知，文案含移交人、转交任务数量，点击跳转到待处理列表；

流程节点处理人替换成功后，新处理人收到一条处理人变更通知，文案含流程模板名称、节点名称、原处理人，点击跳转到发起审批页；

通知复用消息中心既有卡片样式与类型图标规则，时间格式为 yyyy-MM-dd HH:mm。

**待确认**

流程节点处理人替换目前为勾选多条后统一替换为同一人；一人多岗时（如同时有人事类、出纳类流程），不同流程可能应换给不同的接手人，是否改为逐条节点单独选择新处理人，待评审确认。

**附：已知说明**

本期仅 qt 品牌测试门店开放，按门店写死控制，不做权限点控制；后续全量开放需补权限点与门店配置；

工作交接含在途任务批量转交、流程节点处理人替换两项，均由员工本人发起、只处理本人名下的任务与节点；权限点移交归入离职交接，工作交接不处理权限点；

工作交接保持简单、不按交接内容分项选人；本人兼多岗时分多次操作，每次勾对应任务转给对应接手人；

历史单据与已生成预警记录保留原责任人，不随交接改写；预警接收人只改在途单据，历史记录不动；

交接双方限同一门店内，不做跨门店交接，不额外设层级限制；

h5 与 web 两端工作交接的数据与记录互通，任一端发起的操作在两端均可查看。
