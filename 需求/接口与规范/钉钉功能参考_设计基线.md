## 一、钉钉整体信息架构（移动端底部五大 Tab）

| Tab | 定位 | 关键内容 |
|---|---|---|
| 消息 | IM + 工作通知聚合 | 单聊/群聊、@我、特别关注、DING、日历/待办快捷入口、工作通知 |
| 协作 | 团队协同容器 | 文档、待办、日历、云盘、邮箱、知识库、便签 |
| 工作台 | 应用入口中枢 | OA审批、考勤打卡、日志、公告、视频会议、智能人事等全部业务应用 |
| 通讯录 | 组织与关系 | 组织架构、部门、角色、群组、好友 |
| 我的 | 个人与设置 | 收藏、状态、通知偏好、隐私权限、主题、多设备登录 |

**设计启发**：业务功能不铺在 Tab 上，而是收口进「工作台」按应用组织；「消息」只做信息 + 通知聚合；「协作」把文档/待办/日历/云盘打包，避免功能散落。

## 三、关键范式（最有参考价值的三个）

### 3.1 消息 / 通知 / 待办 三分法
- **消息 = 信息流**：历史记录，可不处理（审批结果、系统公告、账单更新）。
- **通知 = 动作流**：状态变化弱提醒（节点完成、资料更新），告知即可。
- **待办 = 责任流**：必须用户完成的动作（审批、补录、确认、签署），强提醒 + 升级。
- 钉钉「消息」内部分组：**@我的、特别关注、私聊、群聊、工作通知、系统提示、免打扰**；外加「消息直通车」一键直达重要消息。
- 可借鉴：按业务类型分组收纳、未读/红点策略、@我 与 待我审批 置顶、免打扰时段。

### 3.2 审批流范式（钉钉 OA 审批）
- 节点可配：审批人类型 = 指定成员 / 发起人自选 / 连续多级主管 / 部门主管 / 直属主管 / 角色 / 表单控件关联。
- 多人审批方式 = 依次、会签（全过才过）、或签（一人过即过）。
- 条件分支（如「请假≥2天走 HR」）、自动通过/拒绝、发起人加签、并行分支、动态流程。
- 全程操作留痕 + 报表 + 与考勤/财务等模块打通（审批结果回流）。

### 3.3 交互与反馈范式
- 卡片化信息呈现、分组收纳（专注模式）、已读/未读一目了然。
- DING 强触达（应用内 / 短信 / 电话多渠道）。
- 红点可配置（按来源、逾期规则：全部提醒 / 仅逾期 / 逾期+今日截止 / 不提醒）。
- 同源短时间多次变更聚合去重（同一单据 3 分钟内多次状态变更合成 1 条，展示最近态）。

## 四、与金阔 OA 当前项目映射

| 金阔 OA 现状 | 钉钉对标 | 可借鉴点 |
|---|---|---|
| 消息中心六类通知（@我的/审批通过/审批驳回/抄送我的/待我审批/还款预警；还款完成归预警子通知） | 工作通知分组 + 消息直通车 | 分组收纳、未读/红点策略、@我 与 待我审批 置顶 |
| 预警管理（还款逾期提醒） | 预警/逾期提醒 + 待办升级 | 预警→待办升级链路、超时催办留痕 |
| 附件上传 / 查看优化 | 媒体文件 + 钉盘 | 图片缩略图、文件类型图标、云盘式查看态 |
| 备用金申请流程 | OA 审批 | 节点 / 审批人 / 条件分支建模 |
| 底部 Tab / 子系统划分 | 五大 Tab + 工作台应用组织 | 业务功能按应用收口，避免散落 |
