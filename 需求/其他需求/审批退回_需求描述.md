**需求描述**

**审批退回 · 操作入口**

通用审批能力：所有审批类型的审批人均可使用退回，h5 与 web 两端操作一致；

审批人处理审批单时，操作在同意、驳回基础上新增「退回」，放在「更多」操作中；

点击退回后填写退回理由（必填），确认后退回生效；

类型配置中每个审批类型增加「允许退回」开关，默认开启，关闭后该类型审批单上不显示退回按钮。

**审批退回 · 退回后的流转**

本期退回对象仅为申请人（发起人）：流程不作废，退回至申请人后原地等待申请人处理；

申请人收到退回通知（站内 + 站外，口径与其他审批通知一致），文案含审批模板名称、退回人、退回理由；

申请人打开审批单修改表单内容后重新提交，重新提交时可修改的字段范围与发起时一致，审批人仍不改动申请内容；

退回后至重新提交前，审批模板如有修改（表单字段、审批流程配置等），申请人重新提交时按重新提交时的最新模板执行，不沿用发起时的旧模板；

重新提交后按全链重走：流程从第一个审批节点重新依次审批，中间已通过的审批节点全部重新审批，走完后流转回退回人所在节点继续审批；

被退回重新审批的节点，原已同意的审批人需要重新审批，之前的同意记录保留在审批记录中并标注「被退回重审」；

流程节点图按时间顺序展示，退回人所在节点标注「退回节点」，位置在「修改后重新提交」之上；重新提交后重新依次审批的节点在节点图中重复出现一行，走完后流转回退回人所在节点继续审批；

会签、或签节点被退回重审时规则不变：会签须全部重新同意，或签任一人同意即通过；

退回后、重新提交前，申请人可以撤销该审批（作废）；重新提交后不能再撤销为退回态，仍按原撤销规则执行；

审批记录完整记录每次退回与重新提交：退回人、退回理由、退回时间、重新提交时间、修改人（申请人本人）。

**审批退回 · 通知**

退回时通知申请人（站内 + 站外，同文案）：文案含审批模板名称、退回人、退回理由三要素；站内复用消息中心既有卡片样式，站外推送点开进审批详情；

通知卡片沿用消息中心既有结构：左侧方形类型图标、标题（未读加粗）、时间、右上未读红点；退回是新增通知类型，图标为橙底「退」字，规格同既有六类；文案中审批模板名用【】，与既有通知一致；

重新提交后通知当前节点处理人，不单独通知退回人：流程从第一个审批节点重新依次审批，轮到哪个节点就通知该节点处理人，文案「{申请人}修改后重新提交了『{审批模板名}』，请重新审批」；退回人在流程流转回其节点时按普通审批收到待办与通知；

退回后、重新提交前申请人撤销的，通知退回人，文案「{申请人}已撤销被退回的『{审批模板名}』，流程作废」；

通知时间格式 yyyy-MM-dd HH:mm，显示在通知详情；卡片里不出现金额，退回理由超长在卡片里截断、详情显示全文。

**审批退回 · 与驳回、撤回的区别**

驳回：审批人终止流程，申请不生效，申请人只能重新发起；

撤回：申请人主动作废审批中的单子，需重新发起；

退回：流程不作废，申请人改完内容重新提交后流程继续走，不打断整单的审批链。

**待确认**

退回范围目前仅支持退回至申请人；是否同时支持退回至之前的任意审批节点（可多选，被退回节点均需重新审批，重审完成后流转回退回人所在节点），待评审确认；

重新提交后按全链重走；是否需要支持「从当前节点继续审批」（退回申请人修改后，中间已通过的节点不重审、不重新通知，直接回到退回人节点），待评审确认。

**附：已知说明**

审批人在单据上不改动申请内容，内容修改只发生在申请人重新提交时；

流程中的审批单申请人不能主动修改表单，只能等审批人退回或自行撤销；已通过的审批单修改与撤销按原规则执行；

同一人既是发起人又是审批人的单据，退回后重新提交，该审批节点同样需要重新审批；

通知复用消息中心既有样式，时间格式 yyyy-MM-dd HH:mm。
