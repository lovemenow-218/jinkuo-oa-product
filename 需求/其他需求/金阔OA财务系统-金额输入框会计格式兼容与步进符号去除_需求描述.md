**需求描述**

**金阔OA财务系统 - 金额输入框会计格式兼容（财务初始余额等金额录入页）**

· 财务系统全部「金额」语义的录入文本框（财务初始余额、凭证金额、收支账户金额等）兼容会计格式数字：用户粘贴或输入含千分位逗号的数字（如 1,234,567.89），系统在失焦或提交时自动去除千分位逗号并归一为标准两位小数 1234567.89；
· 金额输入框解析与归一按以下固定顺序执行（失焦或提交时触发）：
  · 全角转半角：全角数字０–９、全角逗号「，」、全角句号「．」统一转半角，如 １，２３４．５６ → 1,234.56；
  · 去空白：剥离全部空格、Tab、Excel 不间断空格，空格作千分位分隔也一并去除，如 1 234 567.89 与 1, 234, 567.89 均 → 1234567.89；
  · 去符号：剥离货币符号（¥、$、元、USD 等，开头或结尾均可，如 1,234.56元 → 1234.56）与一个可选的前导加号「+」（如 +1,234.56 → 1234.56）；
  · 定正负：前导负号 -1,234.56 → -1234.56；尾部负号 1,234.56- → -1234.56；Excel 括号 (1,234.56) → -1234.56；
  · 留数字：仅保留数字与至多一个小数点，其余字符（字母、单位后缀如万/笔、百分号 %、科学计数 E/e、多个小数点等）拦截并提示；
  · 归一两位小数：不足补零（1234 → 1234.00、1234.5 → 1234.50），超出两位按四舍五入处理。
· 金额输入框限制最大可输入长度：达到上限后阻止继续键入与粘贴并提示「金额长度超限，请检查」；该约束用于防止位数过多导致数值溢出或被序列化为科学计数法（如 -1.01e+24）而报错。后端数据库字段精度已由用户确认放宽至 20 位（2026-11-11）；前端最大可输入长度上限应与之匹配（建议整数位不超过 20 位 + 小数 2 位），前端须以字符串或 Decimal 思路承接金额，避免 20 位整数超出 JS number 安全整数上限 2^53（≈9.007e15）而静默丢精度；具体整数/小数位分配与是否强制截断待与开发最终确认；
· 兼容场景：整段粘贴、手动键入、Excel 复制整列粘贴到批量框；
· 非金额输入框（科目编码、名称等）不生效。

**金阔OA财务系统 - 去除输入框步进符号（− / +）**

· 移除金额输入框右侧的「−」「+」步进按钮（原生 number 输入的 spinner 或组件库 stepper），仅移除该控件；
· 不改变输入框本身的尺寸、占位符、对齐、字体、边框等视觉样式（即只加功能、不改变 UI）；
· 实现建议：将控件由 type=number（或带 stepper 的封装组件）改为 type=text 并叠加上述解析逻辑，或禁用 spinner 样式，保持输入不受符号限制（正负号、货币符号均允许），但须遵守上方「最大可输入长度」约束；
