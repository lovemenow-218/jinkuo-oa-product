**备用金还款预警 - 监控范围与流程状态校验（h5 与 web 共用）**

预警数据来源为备用金申请 OA 审批流程中「会计审批」环节填写的【还款日期】字段，该字段由《备用金审批-会计审批页面优化（还款日期）》需求提供；

仅当该笔备用金申请流程「全部审批通过」时才进入预警监控，即流程已走完会计审批环节与出纳办理环节、处于已办结状态；

流程仍在审批中时（包含会计审批已通过但出纳办理尚未办理的情况）不产生任何预警提醒；

流程被驳回、撤销或作废时不产生任何预警提醒，已发出的预警同时作废，不再继续触发；

还款期长度由【还款日期】与该笔备用金「会计审批」环节审批通过日之间的天数确定，会计审批人在设置【还款日期】时可填写一个月、一年等任意天数，实际可能为 30 天、40 天、50 天、90 天、100 天、200 天、365 天等非固定值；

预警档位以【还款日期】为唯一基准，按「当前日期与【还款日期】之间的剩余天数」判定，与流程发起时间无关；

监控启动后若当前剩余天数已低于某一档位阈值，直接进入当前所处档位并发出对应提醒，不再补发此前已越过的档位提醒；

【还款日期】在会计审批通过后不可修改，如需调整还款期只能重新发起新的备用金申请，新单据按新的还款日期独立计算预警档位，原单据档位不受影响。

**备用金还款预警 - 档位触发规则（h5 与 web 共用）**

预警档位按【还款期天数 T】计算，T =【还款日期】−【会计审批通过日】的天数；

**还款期上限为一年**（业务确认：备用金最多一年；日历 +1 年口径下闰年可达 366 天），故 T ≤ 366 天，全系统只有一套档位规则，不存在超过一年的单据；

每笔单据的预警档位由若干触发点构成，每个触发点对应一次提醒，档位数量随 T 自适应，不固定为四档；

每个档位在同一笔单据上只触发一次，定时任务重复执行不产生重复通知；

多个档位落在同一天时合并为一条通知发送，不重复推送；

<span style="color:#c00000">· 同一笔单据、同一档位、同一接收人的幂等标识为「单据编号 + 档位 + 接收人 + 规则版本（v2）」；规则版本用于隔离新旧档位语义，避免同一语义重复推送；</span>

还款期短于 1 天的单据不产生提前预警，直接进入逾期提醒；

单据办结进入监控时已超过还款日期的（如出纳办理滞后），不再补发任何档位提醒，首条提醒即为逾期提醒，逾期天数自还款日期次日起算，首条即标注实际逾期天数（如「已逾期 5 天」）；

还款日期为审批通过当日（还款期 T=0）的单据，当天无任何档位提醒，次日起进入逾期提醒；

完整档位对照表与 1 ~ 366 天（含闰年）逐日明细见附件《预警档位明细_一年》，开发按表实现即可，无需自行推导。

<span style="color:#c00000">· <b>存量单据口径（本次新增）</b>：新规则（v2）上线后仅对该笔单据尚未触发的档位生效；已发出的旧 v1「还款期过半」档提醒不撤回、不补发、不折算成 30% 档，已触发档位的幂等记录保留旧规则版本；新单据与未触发档位统一按 v2 计算。</span>

**档位规则｜相对档 + 固定档（适用全部单据，T ≤ 366 天，含闰年）**

<span style="color:#c00000">· 候选触发点由五个点构成：提前 30%（相对档，R = ⌈0.3 × T⌉ = ⌈3T/10⌉，整数实现避免浮点误差）、还剩 30 天（仅 T > 60 天时启用）、还剩 7 天、还剩 1 天、到期当天（还剩 0 天）；</span>

到期当天档与「剩余 1 天」临近档、「已逾期」逾期档区分，代表「今天就是还款日」；

候选点中剩余天数大于或等于还款期天数的予以剔除，该档位落在还款日当日或之后、不触发；

剔除后剩余天数相同的候选点合并为一档，只发一次提醒；

<span style="color:#c00000">· <b>相对档门槛（R ≥ 40，本次新增）</b>：30 天固定档启用后（T > 60），相对档须满足 R ≥ 40 才保留，即比 30 天档至少再早 10 天（等价于 T ≥ 131）；R &lt; 40 时舍弃相对档，由「还剩 30 天」档单独承担提前提醒；T ≤ 60 时 30 天档未启用，相对档不受此门槛约束；</span>

**去重规则（D = 3）**：相对档与任一保留的固定档（30 / 7 / 1 天）相差不超过 3 天时视为语义重复，舍弃相对档、保留固定档；「还剩 1 天 → 到期当天」是语义必需对，不参与去重；

合并去重后的档位按剩余天数由大到小排序，即为该笔单据的实际档位序列；

**备用金还款预警 - 逾期提醒（h5 与 web 共用）**

还款日当日已通过「到期当天」档单独提醒，故逾期阶段自【还款日期】次日（即逾期首日）起、对仍未确认还款的单据每天固定时间发出逾期提醒；

逾期提醒每天新增一条独立的通知记录，不合并为一条、不覆盖更新，同一笔单据在列表中按天各占一条；

逾期提醒同时发送给该笔单据的申请人与该笔单据的会计审批处理人，两人各收到一条，文案不同；

申请人的逾期文案：【{流程名称}】已于 {还款日} 逾期 {逾期天数} 天，请立即还款；

会计审批处理人的逾期文案：【{流程名称}】申请人 {申请人姓名} 尚未还款 {金额}，还款日 {还款日}，已逾期 {逾期天数} 天，请关注；

逾期天数按「已逾期 N 天」每日递增，每条逾期通知记录上标注该条产生当日的逾期天数；

逾期提醒的幂等标识为「单据编号 + 提醒日期 + 接收人」，同一天重复执行不产生重复记录；

逾期提醒持续发送，直至该笔单据被确认已还款。

**备用金还款预警 - 通知分类与展示（h5）**

预警通知按接收人角色生成文案不同的两条通知记录，一条发给申请人，一条发给该笔单据的会计审批处理人；

申请人收到的文案：【{流程名称}】将于 {还款日} 到期，剩余 {剩余天数} 天，请及时还款；

会计审批处理人收到的文案：【{流程名称}】申请人 {申请人姓名} 尚未还款 {金额}，还款日 {还款日}，剩余 {剩余天数} 天，请关注；

申请人「到期当天（剩余 0 天）」文案：【{流程名称}】今日 {还款日} 到期，请立即还款；

会计审批处理人「到期当天（剩余 0 天）」文案：【{流程名称}】申请人 {申请人姓名} 尚未还款 {金额}，今日 {还款日} 到期，请关注；

展示口径说明：上述会计审批处理人文案为**通知正文**，h5 / web 消息中心列表卡片主文案、h5 详情弹层副标题、web 详情弹窗与站外推送统一使用该文案；站内卡片主文案最多展示两行，超出以省略号截断；文案中金额直接跟数字、不加括号与货币符号（如「尚未还款 1.00」），站外推送同文案；带货币单位的完整金额在详情弹层 / 弹窗的金额字段中展示；还款日、剩余 / 逾期天数均在文案内承载，不在信息区重复；

预警通知卡片包含左侧类型图标（以「警」字标识）、主文案与两行信息区：第一行为状态 / 阶段标签，第二行为通知时间（yyyy-MM-dd HH:mm）；卡片不再单独设金额行，金额与还款日由主文案承载；

<span style="color:#c00000">· 申请人侧卡片第二行展示阶段标签（常规提醒 / 临近提醒 / 逾期提醒 / 已还款），不展示「提前 30%」等档位标签；</span>

剩余天数统一以「天」为单位展示，不折算为月或年，以保证任意天数的还款期下表述准确；

卡片颜色按所处阶段区分，具体见「阶段颜色标识」；

逾期阶段的每日提醒按天新增记录，新增记录计为未读，保证用户每日都能看到最新的逾期天数。

**备用金还款预警 - 会计审批处理人消息通知列表样式（h5 与 web 共用）**

会计侧预警卡片不提供行内操作按钮；会计审批处理人点击卡片（含未读卡片）即打开详情弹层，在弹层内完成【确认已还款】，避免列表内误触，确认效果与弹层内操作一致；

会计侧预警卡片信息区为两行结构：第一行为【待确认还款】【已逾期 N 天】等确认状态标记，第二行为通知时间（yyyy-MM-dd HH:mm）；金额与还款日由主文案承载，不在信息区重复；

未确认还款的预警卡片带【待确认还款】标记，逾期阶段的卡片同时带【已逾期 N 天】标记；

<span style="color:#c00000">· h5 端会计侧预警卡片第二行仅保留【待确认还款】【已逾期 N 天】【已还款】等确认状态标记，不显示「常规提醒」「临近提醒」「逾期提醒」阶段标签与「提前 30%」档位标签；</span>

逾期阶段的每日提醒在会计侧同样按天新增一条并在列表中堆叠，各卡片分别标注产生当日与已逾期天数，便于会计审批处理人核对逾期进程；

申请人侧的预警卡片不展示【确认已还款】快捷按钮，申请人只接收提醒。

**备用金还款预警 - 已还款确认与预警终止**

单笔备用金的预警终止条件为该笔单据被确认「已还款」，确认后立即停止该单据的所有后续预警与逾期提醒；

确认入口为该笔单据的预警通知详情（h5 详情弹层 / web 详情弹窗）与流程详情中的「确认已还款」操作，会计侧列表卡片点击进入详情弹层后确认（列表内无行内按钮）；各处为同一操作且相互联动；任一处确认后，该笔单据此前生成的全部预警卡片（含列表中按天堆叠的多条）与该笔单据的预警详情页（会计侧）同步隐藏「确认已还款」并提示已还款；

操作权限仅限该笔单据的会计审批处理人，申请人及其他角色不可见该操作；

点击「确认已还款」时弹出二次确认弹窗，弹窗内展示流程名称、申请人、金额、还款日期与当前逾期天数（未逾期时该项显示「—」，不展示 0 天），并明示「确认后该笔备用金将停止所有预警与逾期提醒，且不可撤回」；

会计审批处理人确认已还款后，该笔单据的预警详情页（会计侧 · h5 与 web）进入「已还款」终态：页面隐藏「确认已还款」按钮，以绿色提示「该笔备用金已还款」，不再提供任何确认入口，与列表卡片的已还款状态一致；

「确认已还款」为终态操作，确认完成后不可撤回、不提供撤回入口；若确认为误操作，只能由开发在后台修正还款状态；

确认完成后，该笔单据此前已生成的预警通知保留在列表中，卡片上标记「已还款」；

申请人侧不提供「确认已还款」操作，申请人侧仅接收提醒；

已还款确认结果需回写至该笔备用金的还款状态，作为预警任务下次扫描时的终止判断依据；

已还款后点击该笔单据的任意预警卡片（会计侧 / 申请人侧同口径），详情弹层 / 弹窗进入「已还款」只读回执态：展示流程名称、申请人、金额、还款日期、还款确认人（会计审批处理人）与还款确认时间，隐藏【确认已还款】等全部操作入口，仅提供关闭；web「预警管理」详情以时间线保留全部历史记录；

会计审批处理人确认已还款成功后，系统自动向该笔单据的申请人发送一条「还款完成」通知（站内，归属还款预警类，计入未读），使申请人对还款结果有主动感知，不依赖其自行点开卡片查看；该通知同时接入站外推送（口径见《信息推送（站外推送）》）；

「还款完成」通知文案（申请人）：【{流程名称}】{金额}，还款日 {还款日}，已由会计审批处理人 {确认人姓名} 于 {确认时间} 确认还款；

申请人点击「还款完成」通知或该笔任一预警卡片，均进入「已还款」只读回执态（规则见上条）；发送该通知后，该笔单据不再向申请人发送任何催还款提醒；

口径说明：通知表述为「会计审批处理人确认还款」，与实际到账解耦——钱是否实际到账属线下行为，系统仅记录确认动作；若确认为误操作，由开发在后台修正后由会计审批处理人重新确认（届时不重复发送通知，以最新确认时间为准）；

「还款完成」通知为一次性记录，幂等标识为「单据编号 + 接收人（申请人）」，确认操作不可撤回、天然幂等，不存在重复发送；

「还款完成」通知是否同步接入站外推送通道，由《信息推送（站外推送）》定义，本需求站内口径如上。

**备用金还款预警 - 阶段颜色标识**

预警通知卡片按所处阶段用颜色区分，共三档：

<span style="color:#c00000">  - 常规提醒（蓝色）：除「剩余 1 天」与「到期当天」以外的全部提前提醒档位，含提前 30% 相对档；</span>

临近提醒（橙色）：剩余 1 天档与到期当天（剩余 0 天）档，代表还款迫在眉睫 / 当日到期；

逾期提醒（红色）：逾期阶段的每日提醒；

<span style="color:#c00000">· 颜色仅作辅助区分，不得仅依赖颜色表达严重程度：web 端列表卡片与 h5、web 两端详情弹窗同时展示阶段标签与天数（如「剩余 1 天」「已逾期 3 天」）；h5 端申请人侧列表卡片第二行同样展示阶段标签，与主文案中的天数表述（如「剩余 110 天」「已于 2026-10-29 逾期 3 天」）共同区分严重程度；</span>

预警通知的类型图标统一使用「警」字标识，h5 与 web 端一致，沿用现有通知卡片的方形圆角图标样式；

颜色取值沿用现有消息通知模块已有色板，不新增品牌色；

已还款状态的卡片统一使用中性色，与三档预警色区分。

**备用金还款预警 - 站外推送（系统外通知）**

还款预警除在站内消息中心 / 通知列表承载外，还需接入系统外推送通道（微信式系统通知），使申请人与会计审批处理人在系统外（手机系统通知 / 类微信消息）也能收到预警提醒；

站外推送的通道形态、文案、接收人、推送频率、幂等、已读同步、已还款终止等规则，统一由《信息推送（站外推送）》需求定义，本需求不重复展开；

还款预警在《信息推送（站外推送）》的六类推送清单中作为其中一类，其站内口径以上述各节为准；
