**消息 Tab 与全局框架**

本需求仅覆盖 h5 / App 端「消息中心」，不改动 web 管理后台的消息中心；

底部导航第 1 个 Tab 由【首页】改名为【消息】，图标与位置不变；【待办】【工作台】【我的】三个 Tab 的名称、图标、顺序与功能保持不变；

改名属文案层调整，同步前端路由页标题、Tab 文案与相关埋点中的「首页」字样；待办页既有子标签【待处理】【已处理】【发起的】【抄送】【费控预警】不改动；

消息首页顶部不设页面标题，仅展示头像、用户名与右上角铃铛；不展示「测试环境」等环境提示条；

铃铛在消息首页常驻展示，不因有无未读而隐藏；有未读时右上角显示数字角标，无未读时不显示角标；

铃铛角标与门店角标采用同一封顶规则：≤99 显示真实数，≥100 显示「99+」；铃铛图标本身不改造；

顶部用户名取当前登录人姓名，不展示账号、手机号与角色标签。

本期不提供头像上传 / 修改入口，消息首页头像统一按当前登录人姓名生成首字头像：中文取姓氏首字、英文取首字母，头像与用户名指向同一人；

首字头像为圆形、项目主蓝深一档（#185FA5）底白字，尺寸与顶部行对齐；不依赖图片资源、不出现破图或灰色人形占位；后续若接入组织头像字段，按「有图用图、无图降级首字」扩展，本期不实现。

**消息首页 - 列表结构**

列表按品牌分组展示当前登录人可见的门店；分组头由品牌标识（本期为两字文字占位）、品牌名与「N 家门店 · 共 X 条消息」组成；

品牌归属按门店名中重复出现的前缀判定；系统代号（JK / QT / UD 等）不与门店名直接对应，分组头一律使用品牌名，不使用代号；

真实系统中所有品牌与门店共用同一个平台 logo，门店无独立 logo，因此门店行左侧不放置图标，仅品牌分组头保留品牌标识位；该位置本期统一使用按品牌名自动生成的两字文字占位，不加载图片、不借用平台 logo 或其他品牌图；

两字占位取品牌名前两个字符自动生成：中文取头两个汉字（辰色酒馆 → 辰色）、纯英文取头两个字母并转大写（kucun → KU）、英文数字混合同样取头两个字符并转大写（K2Supply → K2），单字品牌取单字；新增品牌无需人工配置；

占位为圆角方块浅底深字，尺寸与分组头行高对齐；正式品牌 logo 素材提供后按品牌逐个替换为图片（本期 8 个品牌全部待替换），替换不影响分组结构与排序；

分组头「N 家门店」必须与该组实际门店行数一致，不得出现声明数与实际行数不符；

门店行由门店名、最新消息时间、右侧未读角标与右箭头组成；门店名单行显示，超长以「…」截断，不折行、不撑高行高；

最新消息时间格式为 yyyy-MM-dd HH:mm，只显示时间戳，不加「最近」等前缀；时间取该门店最后一条消息的产生时间，不是被读时间；

门店行不展示【商家管理员】/【成员】等角色标签，也不重复展示所属品牌名；

门店行字号：店名 16px / 600、时间行 12.5px、品牌分组头 15px；顶部用户名 17px、角标 11~12px、底部 Tab 11px、通知列表 15 / 13 / 12px 均沿用既有口径；小屏降级时时间行 11.5px；

点击门店行进入该门店消息页；点击右箭头与点击整行等价。

**消息首页 - 品牌 / 门店空态与默认态**

品牌下门店全部无未读时，该分组头合计为 0，分组仍展示、不自动隐藏，0 以弱化样式呈现、不计入全站总数；

当前登录人所有品牌、所有门店均无未读时，消息首页仍整列展示全量品牌分组结构与各门店行，不隐藏、不收起为「无通知」整列空状态；

「无通知」空状态仅在该用户点进某门店消息页、且该门店自身零消息时展示于门店消息页，不作用于消息首页整列；

进入消息首页，品牌分组默认态按未读合计判定：合计未读 > 0 → 默认展开；全 0 → 默认折叠（仅展示分组头）；

门店子级随父级：父级展开则门店全列、不二次折叠；父级折叠则仅展示分组头，点击展开即列出全部门店行；

不提供全局「全部展开 / 全部折叠」开关；不记忆用户手动展开 / 折叠状态，每次进入消息首页均回到上述默认态，跨会话不持久化。

**消息首页 - 计数与排序口径**

门店右侧角标 = 该门店的未读消息数；未读为 0 的门店不显示红底未读角标；

分组头「共 X 条消息」中的 X = 该品牌下所有门店未读消息数之和，与门店角标同一口径，不是该品牌的历史消息总量；

汇总弹窗标题的全站总数 = 各品牌 X 之和；铃铛角标 = 同一总数的封顶显示（≥100 显示「99+」）；

门店角标、分组头、汇总弹窗、铃铛四处必须使用同一份未读数实时计算，不得各自缓存或采用不同口径；

排序规则：品牌分组按合计降序；同组内门店按角标降序，角标相同按最新消息时间倒序（时间新的在前）；

角标相等且最新消息时间缺失（门店无消息历史）或相等（最后消息同秒产生）时，启用名称兜底排序，顺序 100% 确定、不依赖数据库返回序、不随机跳序；

名称兜底按中文拼音首字母（金 jīn → J、阔 kuò → K，首字母相同再比后续拼音）、名称中阿拉伯数字按自然排序（门店2 < 门店10，非字典序门店10 < 门店2）、中英文混排并入同一序列比较；

品牌级全 0（各品牌合计相等）时品牌之间按品牌名拼音首字母兜底排序；门店级全 0 时门店之间按门店名拼音首字母兜底排序，无历史（null 时间）门店不再置底悬空、统一并入名称序；

封顶显示「99+」的角标参与求和时按封顶前真实值计算；原型演示中首店「99+」实为 156，否则该组 418 无法加平；

汇总弹窗的品牌行顺序与消息首页分组顺序完全一致，不另排一套；无消息品牌显示 0 且不计入总数；

计数与排序由服务端随列表接口一并返回，前端不自行累加或重排；分页时仍需返回全量汇总，避免跨页数字错误；

原型演示值为全站 1207、8 组依次 418 / 370 / 133 / 107 / 52 / 48 / 48 / 31，仅用于校验四处数字与排序自洽，联调以接口真实返回为准。

**消息首页 - 搜索**

搜索框位于顶部用户名行下方、列表上方，占位文案「搜索门店 / 品牌」；

支持模糊匹配与关键字匹配：品牌名、门店名、括号内地名、数字、后缀（供应链 / 美食 /（新）/【小卖部】）、中英混排片段、空格分词均可命中；

搜索结果沿用按品牌分组的结构，组内沿用默认排序；命中品牌时展示该品牌下全部门店，命中门店时仅展示命中的门店；

搜索不改变铃铛、分组头等未读计数口径，仅过滤展示范围；

仅消息首页提供搜索，门店消息页内不提供搜索入口；

需覆盖无结果状态（「未找到相关门店」）与清空搜索后恢复全量列表。

**铃铛与消息汇总弹窗**

点击铃铛在铃铛下方浮出「消息汇总」弹窗，不跳转页面；弹窗出现时背景仍为完整消息首页，不做整页遮罩替换；

弹窗标题为「消息汇总」，右侧显示全站消息总数（与铃铛同一口径的未读总数，此处显示真实值、不封顶）；

弹窗列表按品牌逐行展示该品牌未读合计，顺序与消息首页品牌分组完全一致（按合计降序）；

无未读的品牌显示 0，以弱化样式呈现并标注无消息 / 滚动占位，0 不计入全站总数；

弹窗列表固定高度、超出可滚动，需能容纳 20 个以上品牌；底部提示「超出可滚动 · 点外部关闭」；

弹窗仅用于展示，行不可点击、不跳转、不触发已读；点击弹窗外部或再次点击铃铛关闭；

弹窗位置锚定铃铛底部（顶部安全区 + 固定偏移），不写死绝对坐标，状态栏高度变化时仍贴合；最大高度取「屏高 − 安全区 − 76pt」兜底，任何机型不超出屏底与右缘；

屏宽 > 520pt 时弹窗跟随内容列右缘而非屏幕右缘；屏高 ≤ 500pt 时改为贴底半屏（限高 56%、列表内滚）并使用紧凑行。

**门店消息页（多门店用户 · 子页）**

由消息首页点击门店进入，页面标题位直接显示该门店名，不出现「通知」二字；长名单行省略；

顶部保留返回箭头，固定返回消息首页门店列表；右上角保留【批量已读】（沿用原文案，不改名）；

标题下方提供【全部 N】【未读 M】两个胶囊，N / M 为当前门店、当前筛选下的条数，选中项蓝底；切换筛选不重新请求全量计数；

列表按当前门店单独取数，不同门店之间消息隔离，不串店、不合并展示；

需覆盖加载中、空状态、错误重试与滚动加载更多；

本页为【消息】Tab 下的子页，保留返回箭头、不显示底部 Tab，避免子页底部仍高亮【消息】造成层级歧义，同时为列表多留出可见空间；

本页不提供搜索。

**单门店用户消息页（根页）**

当前登录人仅拥有 1 家门店时，进入 App【消息】直接进入该门店消息页，不展示品牌 / 门店列表；

顶部显示该门店名，不显示铃铛、不显示返回箭头（无上级页）；

列表样式、筛选胶囊、【批量已读】与门店消息页一致，按该门店取数；

本页是【消息】Tab 的根页，必须保留底部 Tab，否则用户无法切换到【待办】【工作台】【我的】；

若后续该用户被授权更多门店，进入【消息】自动切回消息首页，单门店直达逻辑不再生效。

**通知类型与列表卡片（C / D 共用）**

消息中心承载站内既有六类通知：@我的 / 审批通过 / 审批驳回 / 抄送我的 / 待我审批 / 还款预警，分类口径与《总的需求文档》§四、《信息推送（站外推送）》一致；本次不新增、不删减通知类型，也不改变各类的生成、文案、接收人与推送逻辑；

「还款完成」是还款预警类下确认已还款后发给申请人的子通知，不单列第七类；

本次需求只改变通知的进入路径与组织方式：由原通知列表入口，改为消息首页按品牌分组 → 点门店进入该门店消息页（C），仅 1 家门店的用户直接进入单门店消息页（D）；六类通知在对应门店页内混排，不按类型分 Tab 或分组；

六类通知的主文案、类型图标、卡片样式与点击落点一律沿用《消息通知优化（h5）》《web 消息通知》《备用金还款预警通知》及总纲既有口径，本次不改动、不重新定义；卡片上不放置行内操作按钮；

未读标题加粗、已读标题常规字重；通知按产生时间倒序，最新在最上；通知被读后不自动移除，仅消除未读标记；

还款预警类沿用《备用金还款预警通知》口径：确认已还款触发还款完成通知（站内 + 站外，申请人接收），该单据全部卡片转灰并停止催提醒，幂等键为「单据 + 接收人」；预警起始时间为单据办结进入监控的时间；逾期站外提醒每天跟随站内发送、不降频；

通知文案中的角色称谓统一为「会计侧（会计审批处理人）」与「申请人」，不使用「财务侧」；卡片与详情弹层均不展示申请人手机号，不提供拨号 / 复制号码，不做号码快照；站外推送仅推文案；

通知只读，卡片上不直接执行审批动作，审批仍需进入流程详情页操作；六类通知均按所属门店隔离展示，门店隔离口径见「权限与数据隔离」。

**已读与状态联动**

逐条点开通知、或在门店消息页点击【批量已读】，均将对应通知标记为已读；批量已读作用范围为当前门店当前筛选下的列表，不跨门店、不清空已有通知；

标记已读后无需返回首页刷新，消息首页对应门店角标、该品牌分组头合计、铃铛角标与消息汇总弹窗数字实时同步下降；

已读联动仅作用于当条通知，不影响同门店其他通知的未读状态；

跨端已读状态实时同步（沿用总纲「跨端已读同步」规范）；

计数随列表接口一并返回，不额外发起独立计数请求；并发已读导致的计数回退以服务端最新值为准。

**底部导航与页面层级**

层级约定：消息首页为【消息】Tab 根页；门店消息页为其子页（去底部 Tab、保留返回）；单门店用户消息页为根页（留底部 Tab、无返回、无铃铛）；消息汇总弹窗为浮层，不占页面栈；

C 的返回箭头固定回到 A 门店列表，不回到上一 Tab、不回到铃铛弹窗；

从【待办】【工作台】【我的】切回【消息】时，回到该用户进入消息中心时的根页（多门店为 A，单门店为 D），不强制回到子页。

弹窗列表固定高内滚并设 max-height 兜底，任何形态下不超出屏底与右缘。

**权限与数据隔离**

数据隔离维度沿用商家主体 businessId，跨主体互不可见、互不读写；门店维度进一步隔离通知，用户仅能看到本人被授权的门店；

门店列表与通知列表均按当前登录人过滤，不展示他人通知、不展示无权限门店的名称与计数；

接口层按身份鉴权，前端隐藏入口不作为权限控制手段；越权访问门店消息返回无数据或 403，不回显门店信息；

不展示门店角色标签，不通过列表暴露账号、手机号等个人信息。

**异常与边界**

配套原型为《消息中心 · 原型设计》（docs/消息中心_原型.html），含 A 消息首页 / B 消息汇总弹窗 / C 门店消息页 / D 单门店用户消息页四屏；文中品牌、门店、人名与计数均为演示值，不代表业务上限，联调以接口真实返回为准；

列表 / 计数接口超时或失败时保留上次成功数据并提示可重试，不把计数清零造成「已读」误判；

无门店、无通知、搜索无结果分别展示对应空状态；

门店名超长、中英混排、同名不同角色的门店均按单行省略展示；同名门店须以不同标识或时间区分，不得合并去重；

同一通知重复投递时按「单据 + 接收人 + 通知类型」幂等去重，计数不重复累加；
