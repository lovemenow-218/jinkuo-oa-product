# 备用金还款预警通知与预警管理接口文档

> 源码核对日期：2026-11-09。本文描述当前仓库 `src/modules/oa/flow/flow.routes.js` 实际注册的 HTTP 契约，供 PC/H5 联调。请求与响应示例中的编号、姓名和时间均为示意值，不代表真实业务数据。

## 1. 范围与公共约定

- **预警通知**复用 OA 消息中心的 `oa_app_notifications` 接口。该接口同时返回其他 OA 通知；目前没有仅查询 `repayment_warning` 的服务端 `type` 筛选参数。`repayment_warning` 是预警卡，`repayment_done` 是确认还款后给申请人的完成回执。
- **预警管理**使用 `oa_repayment_warnings` 接口。台账在合格备用金单据办结时形成一单一行；即使尚未产生提醒也可在台账出现，确认后继续保留。
- 以下路径均以服务实际地址为前缀。本地配置默认 `http://localhost:8001`，实际端口以部署配置 `PORT` 为准。
- 所有接口需要有效 OA 登录上下文。可使用 `Authorization: Bearer <token>`、`syOpenAppToken: <token>` 或登录 Cookie（默认 `jkoa_token`）。生产环境的账号、门店、员工身份从令牌取得；`x-account-id` 等请求头仅可用于开发/测试环境，不是生产接入方式。请求中的门店或员工标识不能替代服务端鉴权。
- 写请求使用 `Content-Type: application/json`。这些兼容路由通过 `readJson` 也可读取表单编码；建议新客户端统一使用 JSON。空请求体传 `{}`。
- 成功响应为 HTTP 200：`{"status":200,"success":true,"msg":"","data":...}`。已识别的业务错误通常以对应 HTTP 状态返回 `{"status":403,"success":false,"msg":"错误说明","data":null}`。客户端应同时判断 HTTP 状态与 `success/status`；这里的错误体没有 `code` 字段。未处理的服务器异常由全局异常处理器返回，格式可能不同。
- 日期字段使用 `YYYY-MM-DD`；`*_at`、`occurred_at`、`completed_at` 均为 **Unix 秒**；`remaining_days` 是按北京时间当前业务日计算的整数，负数表示逾期。读台账或详情不会标记通知已读。

## 2. 接口总览

| 场景 | 方法 | 路径 | 权限与作用 |
| --- | --- | --- | --- |
| 通知列表与未读数 | GET | `/oa_sys/business/oa_app_notifications` | 当前收件账号 |
| 通知详情 | GET | `/oa_sys/business/oa_app_notifications/:id` | 当前收件账号 |
| 单条已读 | POST | `/oa_sys/business/oa_app_notifications/:id/read` | 当前收件账号，修改本条已读状态 |
| 全部已读 | POST | `/oa_sys/business/oa_app_notifications/read-all` | 当前收件账号，修改其所有类型的未读通知 |
| 预警台账 | GET | `/oa_sys/business/oa_repayment_warnings` | 有 `sy-org-admin` 门店关系的账号 |
| 预警导出 | GET | `/oa_sys/business/oa_repayment_warnings/export` | 同台账权限与筛选 |
| 预警详情及时间线 | GET | `/oa_sys/business/oa_repayment_warnings/:id` | 本单实际申请人、会计或本店组织管理员 |
| 单笔确认已还款 | POST | `/oa_sys/business/oa_repayment_warnings/:id/confirm` | 本单实际会计审批处理人 |
| 批量确认已还款 | POST | `/oa_sys/business/oa_repayment_warnings/confirm-bulk` | 每笔分别复核实际会计身份 |

路由中的 `:id`：通知接口是**通知 ID**，预警管理接口是**OA 流程单据 ID**（`record_id`），二者不可混用。

## 3. 预警通知接口

### 3.1 查询通知列表和未读数

`GET /oa_sys/business/oa_app_notifications?filter=all&limit=20`

| 查询参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `filter` | `all` \| `unread` | `all` | 查询全部或仅未读；不按通知类型过滤。非法值返回 400。 |
| `limit` | 正整数 | 20 | 每页数量，上限 100；非法值回退 20，超过上限截为 100。 |
| `last` | 字符串 | 无 | 上一页的 `next_last`，原样透传；非法游标返回 400。 |

`data` 结构：

```json
{
  "items": [
    {
      "id": 101,
      "type": "repayment_warning",
      "title": "备用金申请 10001 距还款日还有4天，请按期还款",
      "actor_name": "有人",
      "form_name": "备用金申请",
      "comment_excerpt": "",
      "record_id": 10001,
      "target_log_id": null,
      "occurred_at": 1794103200,
      "read": false,
      "warning_confirmed": false
    }
  ],
  "unread_count": 1,
  "has_more": false,
  "next_last": null
}
```

`items` 按 `occurred_at DESC, id DESC` 排序。`next_last` 非空时用它取下一页；`unread_count` 是当前账号**所有通知类型**的未读总数，不受 `filter` 或 `limit` 限制。只有 `repayment_warning` 项带 `warning_confirmed`；确认后原预警卡的标题和已读事实不变，该字段变为 `true`。`repayment_done` 是独立通知，不带此字段。`title` 为通知创建时的文案快照，台账中的剩余天数和阶段则按当前业务日重新计算。

### 3.2 查询单条通知

`GET /oa_sys/business/oa_app_notifications/:id`

响应 `data` 是与列表 `items[]` 相同的通知对象。通知必须属于当前账号；对预警卡会重新读取当前还款确认状态，以填充 `warning_confirmed`。非法通知 ID 返回 400；不存在或不属于当前账号返回 404。该接口本身不标记已读，也不授予预警单据详情权限。

### 3.3 标记单条已读

`POST /oa_sys/business/oa_app_notifications/:id/read`

预警卡请求体：`{}`。成功时 `data` 示例：

```json
{ "unread_count": 0, "read": true }
```

仅更新当前收件账号的该通知；重复标记可再次调用。`read` 表示本次查询后该卡是否已读。通用消息中心的 `mention` 类型可另传 `target_log_id` 防止聚合评论变更时误读；预警卡不需要该字段。PC 预警弹窗在单条通知和预警详情均成功读取后才调用本接口；若详情失败，不应仅因点击卡片就标记已读。

### 3.4 标记当前账号全部已读

`POST /oa_sys/business/oa_app_notifications/read-all`

请求体：`{}`；成功 `data`：`{"unread_count":0}`（并发新通知到达时也可能大于 0）。作用于当前账号的**所有 OA 站内通知**，不局限于备用金预警，无法传 `type` 限定范围。

## 4. 预警管理接口

### 4.1 查询台账

`GET /oa_sys/business/oa_repayment_warnings`

| 查询参数 | 类型/取值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `business_id` | 正整数 | 全部已授权门店 | 只能指定当前账号具有 `sy-org-admin` 关系的门店；指定无权门店返回 403。当前实现对非正整数/非数字不加门店筛选。 |
| `keyword` | 字符串 | 无 | 单据 ID 精确匹配，或流程名称、申请人、部门包含匹配；文本最多取前 80 字符。 |
| `applicant` | 字符串 | 无 | 申请人姓名快照包含匹配，最多 80 字符。 |
| `department` | 字符串 | 无 | 部门名称快照包含匹配，最多 80 字符。 |
| `stage` | `normal` / `near` / `overdue` / `repaid` | 无 | 阶段筛选；非法值返回 400。 |
| `status` | `active` / `overdue` / `repaid` | 无 | 状态筛选；`active` 包含 `normal` 与 `near`，非法值返回 400。与 `stage` 同传时取交集。 |
| `repayment_from`、`repayment_to` | `YYYY-MM-DD` | 无 | 还款日期起止，均含边界。当前路由未单独校验日期文本格式，调用方应按格式传值。 |
| `sort_by` | `repayment_day` / `completed_at` / `amount` / `applicant` / `record_id` | `repayment_day` | 非枚举值回退到还款日排序。 |
| `sort_order` | `asc` / `desc` | `asc` | 只有 `desc` 使用倒序，其他值按升序处理；同值时以 `record_id` 同方向稳定排序。 |
| `page` | 正整数 | 1 | 非法值回退 1。 |
| `limit` | 正整数 | 20 | 上限 100；非法值回退 20。 |

响应 `data` 示例：

```json
{
  "items": [
    {
      "record_id": 10001,
      "business_id": 101,
      "form_name_snapshot": "备用金申请",
      "applicant_name_snapshot": "示例申请人",
      "department_name_snapshot": "财务部",
      "amount_snapshot": 1000,
      "approved_day": "2026-10-01",
      "repayment_day": "2026-11-12",
      "completed_at": 1794000000,
      "confirmed_at": null,
      "invalidated_at": null,
      "remaining_days": 3,
      "stage": "near",
      "can_confirm": false
    }
  ],
  "total": 1,
  "summary": { "total": 2, "active": 1, "overdue": 1, "repaid": 0 },
  "page": 1,
  "limit": 20
}
```

`total` 是当前筛选命中行数；`summary` 始终汇总当前账号**全部获授权门店**的监控单据，不受筛选和分页影响。`can_confirm` 是服务端给当前账号的操作提示，真正提交确认时仍重新鉴权。`amount_snapshot` 是办结时的金额快照。`invalidated_at` 非空的行仍可能出现在台账，但不能确认。`stage` 按当前北京时间业务日计算：已确认优先为 `repaid`；否则 `remaining_days<0` 为 `overdue`，`0..7` 为 `near`，`>7` 为 `normal`。阶段不等于当天是否实际产生过通知。

### 4.2 查询单据详情及预警时间线

`GET /oa_sys/business/oa_repayment_warnings/:id`

`data` 包含上表单条台账的全部字段及 `events` 数组。示例：

```json
{
  "record_id": 10001,
  "business_id": 101,
  "form_name_snapshot": "备用金申请",
  "applicant_name_snapshot": "示例申请人",
  "department_name_snapshot": "财务部",
  "amount_snapshot": 1000,
  "approved_day": "2026-10-01",
  "repayment_day": "2026-11-12",
  "completed_at": 1794000000,
  "confirmed_at": null,
  "invalidated_at": null,
  "remaining_days": 3,
  "stage": "near",
  "can_confirm": false,
  "events": [
    {
      "id": 201,
      "kind": "tier",
      "rule_version": "v2",
      "tier_family": "7",
      "threshold_days": 7,
      "business_day": "2026-11-08",
      "remaining_days": 4,
      "stage_label": "提前7天",
      "occurred_at": 1794103200
    }
  ]
}
```

`events` 按 `occurred_at, id` 升序，记录真实已生成的内部预警事件及确认事件；空数组表示还没有事件。`kind` 可能为 `tier`、`overdue`、`repaid`；`tier_family`、`threshold_days` 对逾期或确认事件可为 `null`；`rule_version` 和 `stage_label` 保留事件生成时的历史事实。详情可由本单当前真实申请人、会计或本门店组织管理员查看；管理员查看不等于有确认权。读取详情不会修改消息中心通知的已读状态。

### 4.3 单笔确认已还款

`POST /oa_sys/business/oa_repayment_warnings/:id/confirm`

请求体：`{}`。首次成功 `data`：`{"record_id":10001,"confirmed":true,"already_confirmed":false}`；有权处理人重复提交时返回 `already_confirmed:true`。服务端核对本单实际会计员工与当前账号的关系、原成功审批日志、单据有效状态及申请人收件账号；仅有管理员或申请人身份不能确认。

首次成功在一个事务内写确认时间和 `repaid` 事件，并给申请人生成一条 `repayment_done` **站内通知**；之后停止该单后续预警扫描。接口没有撤销操作，调用前应由用户核对单据。再次确认不会重复生成完成通知。

### 4.4 批量确认已还款

`POST /oa_sys/business/oa_repayment_warnings/confirm-bulk`

```json
{ "record_ids": [10001, 10002] }
```

`record_ids` 必须是包含 1–100 个编号的数组；编号须为正安全整数，重复编号只处理一次。请求整体格式错误返回 400；格式有效后每笔独立处理，单笔失败不会回滚其他成功项。返回 `data` 示例：

```json
{
  "results": [
    { "record_id": 10001, "confirmed": true, "already_confirmed": false },
    { "record_id": 10002, "confirmed": false, "error": "只有本单会计处理人可以确认" }
  ]
}
```

调用方应逐条检查 `results[].confirmed`，不能仅凭批量接口 HTTP 200 判断全部成功。每笔成功的站内完成回执与单笔接口相同。

### 4.5 导出台账

`GET /oa_sys/business/oa_repayment_warnings/export`

接受与台账列表相同的**门店、文本、阶段、状态、日期和排序**查询参数；`page`、`limit` 不用于导出。服务端使用同一授权与筛选口径，最多导出 50000 行，超过则返回 400，不会静默截断。接口返回 JSON，**不是文件下载流**：

```json
{
  "filename": "备用金还款预警.csv",
  "csv": "\uFEFF单据编号,门店编号,申请人,部门,金额,还款日期,剩余天数,阶段,确认时间\r\n..."
}
```

上例是 `data` 内容；`csv` 为带 UTF-8 BOM 的 CSV 文本，字段顺序如表头。PC 页面目前在浏览器把该文本转换为 `.xlsx` 下载，第三方调用应自行按 CSV 处理，不能把接口响应当二进制 Excel 文件。

## 5. 常见错误与调用顺序

| HTTP 状态 | 场景 | 业务说明 |
| --- | --- | --- |
| 400 | 无效通知 ID/游标/筛选，单据 ID 错误，批量编号格式错误，导出超过 50000 行 | 修正请求参数。 |
| 401 | 缺少有效 OA 账号、门店或员工上下文 | 重新登录或检查令牌声明。 |
| 403 | 无台账门店管理关系、查看无关单据、非本单会计确认 | 由对应业务鉴权返回。 |
| 404 | 通知不存在或不属于当前账号；预警监控单据不存在 | 预警详情要求该单已进入监控台账。 |
| 409 | 确认时原审批事实缺失、单据失效或申请人收件关系变化 | 需核对业务事实后处理；不能仅重试覆盖。 |

PC/H5 预警卡建议调用顺序：通知列表 → 单条通知 → 对应 `record_id` 的预警详情 → 成功展示后标记该通知已读；有 `can_confirm` 时可提交单笔确认，再刷新详情及通知列表。台账列表/导出只面向有管理门店关系的账号；普通申请人或会计仍可按单据权限读取自己参与的预警详情。

预警事件和通知由合格单据办结后的本单扫描、以及独立 Worker 每天北京时间 10:00 后的扫描写入；没有面向客户端的“发送预警”接口。当前实现仅生成站内通知，不调用站外推送。若独立 Worker 未运行，台账的实时阶段仍可能变化，但不会据此自动出现当天通知。
