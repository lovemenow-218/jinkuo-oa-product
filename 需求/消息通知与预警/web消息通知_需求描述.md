**需求描述**

**web 消息通知 - 顶部入口**

在 web 管理后台顶部导航栏右侧的「对话气泡」图标（原无功能）设为消息通知入口；

图标旁实时显示当前用户未读消息数量，以黑色数字文本呈现（如「3」），无未读时不显示；

有新消息到达时，角标数字与消息列表自动刷新（前端定时拉取或服务端推送），无需手动刷新页面；

点击该图标，直接跳转至独立的「消息中心」页面。

**web 消息通知 - 消息中心列表展示**

消息中心以时间倒序列表展示当前用户收到的全部通知；

每条通知统一由四部分组成：左侧类型图标、主文案（含流程名与关键动作）、来源流程名与时间、未读标记（未读条目左侧加色条并加粗）；

列表顶部提供「全部 / 未读」筛选切换，切换后列表实时过滤；

列表提供「批量已读」按钮，点击将当前筛选结果下的全部未读通知标记为已读（仅标记已读，不做清空删除）；

点击单条通知，立即将该条标记为已读，并跳转至对应流程详情页（定位到该通知关联节点或评论）；

列表为空（无任何通知）时展示空状态提示；筛选「未读」且无未读时同样展示对应空状态；

列表滚动加载更多（游标沿用 last + limit，与 h5 端一致），加载到末页提示「没有更多了」；需覆盖加载中、加载失败可重试状态；

未读角标数字随列表接口一并返回，不额外发起计数请求；并发已读导致的计数回退以服务端最新值为准。

**web 消息通知 - 通知分类与内容规则**

通知共五类，与 h5 端一致，每类展示规则如下：

@ 我的：流程内参与人（不含管理员）在评论中 @ 当前用户时生成；主文案为「【评论人】在【流程名称】流程@了你：{评论摘要片段}」；点击跳转流程详情的评论位置；

审批通过：当前用户发起或被指派审批的节点审批通过时生成；主文案为「【流程名称】的【节点名称】已由【审批人】审批通过」；点击跳转该流程详情对应节点；

审批驳回：当前用户发起或被指派审批的节点被驳回时生成；主文案为「【流程名称】的【节点名称】已被【审批人】驳回」；点击跳转该流程详情对应节点；

抄送我的：当前用户被设为某流程抄送人时生成；主文案为「【流程名称】已抄送给你，可查看审批进度」；点击跳转该流程详情。

待我审批：流程流转到当前用户、当前用户成为某节点的待审批处理人时生成（提交后进入首个审批节点、上一节点通过后流转到下一节点、会签/或签节点的全部处理人）；主文案为「【提交人】提交了【流程名称】，请处理」，该文案不分场景，统一适用于上述所有"流转到您"的提醒（含会签/或签节点），不做场景区分；点击跳转该流程详情对应节点；

五类通知共用同一列表与同一套已读/筛选/批量逻辑，仅在类型图标与主文案上区分；

「待我审批」类为本次新增第 5 类，服务端需新增生成与落库逻辑（沿用 oa_flow_msg 接口，与其余四类同表）；触发时机为流程流转到当前用户、其成为某节点待审批处理人时；

待我审批通知与【审批任务 - 待我处理】并存：待办承载「可操作的清单」，本通知承载「流转到您的事件提醒」，接收人一致、同一单据会同时出现，属预期行为；本通知只读，不支持在卡片上直接审批，仍需进入流程详情页操作；

**web 消息通知 - 已读状态与跨端同步**

已读逻辑与 h5 端一致：单条点击即已读、支持「全部 / 未读」筛选、支持批量已读；

web 端与 h5 端共用同一套已读状态，在 web 端将某条通知标为已读后，h5 端同步视为已读（跨端同步）；

通知保留期限沿用 h5 端决策（不做自动清理）。

**附：已知说明**

五类通知的生成、文案、@ 摘要、选人限制、已读/筛选/批量逻辑均沿用 2026-10-28 已交付的 h5 端消息通知优化决策，本需求不重新设计；

「待办」在 web 端为独立菜单（【审批任务】），不在消息中心内聚合；

本需求仅覆盖 web 管理后台，不含 h5 端改动；

顶部消息入口对应原无功能的「对话气泡」图标；角标为图标旁的黑色数字文本，有新消息自动刷新；

点击消息图标直接跳转独立消息中心页（非下拉气泡、非右侧抽屉）。
