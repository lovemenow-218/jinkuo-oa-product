## 三、造数与观测模型

```
建备用金申请 → 会计审批填还款日(T = 还款日 − 会计审批通过日) → 出纳办理 → 全部办结
   → 台账一单一行（即使未产生提醒也入台账；stage ≠ 当天是否发过通知）
   → 本单扫描 / Worker 10:00 后扫描 → events（tier / overdue / repaid）
   → 站内通知 oa_app_notifications：申请人 1 条 + 会计侧 1 条（文案不同）
   → 确认已还款 → repayment_done 给申请人 1 条 + 全部预警卡转灰 + 停止扫描
```

**三个独立 oracle**（避免"列表和导出/通知同源一起错、一致性却通过"）：
1. `docs/预警档位明细_一年.csv`（366 行，RULE_VERSION=v2、GATE=40）—— 档位序列期望值；
2. 需求文案模板 —— 通知主文案、阶段标签、卡片信息区期望值；
3. 跨接口交叉 —— `events` ↔ 通知 `items[]` ↔ 台账 `stage/remaining_days` ↔ 详情回执态。

**值规范化白名单**（逐格比对前必做）：`title` 是通知创建时的**文案快照**，台账 `remaining_days`/`stage` 按当前业务日**实时重算**；金额 `40` vs `40.00`；`*_at` Unix 秒 vs `YYYY-MM-DD`；枚举 code vs 中文；`null` vs `—`/`-`；UTF-8 BOM 与 `\r\n`。
