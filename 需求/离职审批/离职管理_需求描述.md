**需求描述**

**离职管理 · 入口与显示范围**

web 左侧菜单「人事」下新增「离职管理」菜单；菜单可见范围与「人事」菜单既有权限一致，HR 与管理员可见，普通员工不可见；

显示范围与工作交接一致，仅 qt 品牌测试门店可见，本期不做权限点控制；

离职管理面向 HR 与管理员；员工发起、审批处理、交接确认属离职审批，见「离职审批」需求文档。

**离职管理列表页 · 页面结构**

点击「人事」→「离职管理」进入列表页，面包屑「人事 / 离职管理」，页标题「离职管理」；

页签三个：离职流程中的员工、已离职员工、离职记录，默认显示「离职流程中的员工」，切页签保留各自的上次查询条件；

每个页签均为「查询区 + 列表」结构，查询区有「查询」「重置」按钮；点击查询或回车按当前条件过滤并回到第 1 页，点击重置清空条件恢复默认列表；

列表分页沿用 web 端既有列表分页样式；列表需覆盖空状态（无数据提示）、加载中、错误态。

**离职管理列表页 · 页签一 离职流程中的员工**

查询区字段：姓名（输入框，模糊匹配）、部门（输入框）、当前阶段（下拉，选项：全部 / 申请中 / 交接中 / 待确认），按钮「查询」「重置」；

列表全部字段：姓名、部门、职位、预计离职日期、当前阶段（标签：申请中 / 交接中 / 待确认）、交接项（已确认数 / 总数，如 2/6）、操作（固定最右侧）；

操作按员工当前阶段显示不同组合：

申请中：查看流程进度、修改离职日期、撤销离职；

交接中：查看流程进度、交接详情、修改离职日期、撤销离职；

待确认：查看流程进度、交接详情、确认离职、修改离职日期、撤销离职；

「确认离职」仅交接全部确认后显示（交接项为 总数/总数），交接未走完的员工不出现确认入口；

页签内列表上方提供「办理离职」按钮，点击弹窗选择办理方式：审批离职、手动办理（见后文两个弹窗）；

预计离职日期早于今天的员工，日期标红提示。

**离职管理列表页 · 页签二 已离职员工**

查询区字段：姓名（输入框，模糊匹配）、部门（输入框）、离职日期区间（起止日期选择），按钮「查询」「重置」；

列表全部字段：姓名、部门、职位、入职日期、离职日期、离职原因、操作（固定最右侧）；

操作：查看流程进度、查看交接详情。

**离职管理列表页 · 页签三 离职记录**

查询区字段：姓名（输入框，模糊匹配）、部门（输入框）、离职日期区间（起止日期选择），按钮「查询」「重置」；

列表全部字段：姓名、入职日期、离职日期、离职时部门、离职时职位、离职原因；只读流水，无操作列；

数据来源：审批离职、手动办理产生的离职动作均记入本页签。

**离职管理 · 办理离职（方式选择弹窗）**

点击「办理离职」打开方式选择弹窗，两个选项：审批离职、手动办理；

审批离职：选择员工后进入离职审批流程发起，表单与审批链见「离职审批」需求；是否允许 HR 代员工发起，见待确认；

手动办理：进入手动办理弹窗。

**离职管理 · 手动办理弹窗**

字段：员工（按姓名 / 工号搜索选择在职员工，选中后带出部门、职位）、离职日期（日期选择，必填）、离职原因（多行文本，必填）；

校验：仅允许选择「在职」员工，已是待离职 / 已离职的员工不可再手动办理，就地提示并拦截；

提交后直接生效：员工状态改为「已离职」，不经审批、不做交接；离职记录页签新增一条记录；

提交中按钮置灰，避免重复提交；成功后关闭弹窗、刷新列表。

**离职管理 · 确认离职 · 交接事项核对页**

从页签一点「确认离职」进入，仅交接全部确认的员工可进入；面包屑「人事 / 离职管理 / 确认离职」；

页标题「确认离职 · 交接事项核对」，标题旁显示员工信息（姓名 · 部门 · 职位）；

交接事项按项逐行展示：交接项名称 → 接收人（姓名 · 岗位），每行带「修改」链接可改该项接收人，接收人候选显示「姓名 · 岗位」、限同门店在职员工；

交接事项下方显示离职日期、离职原因，带入申请信息，可修改；

底部按钮「上一步」（返回列表页）、「确认并下一步」；点击「确认并下一步」后执行「确认离职」，执行前弹二次确认提示「确认离职不可撤销」；

执行中按钮置灰显示「确认中…」，避免重复提交。

**离职管理 · 确认离职执行（自动动作）**

确认后系统自动执行，无需人工二次操作：离职日期写入员工档案；剩余待办按交接项转给各自接收人；回收该员工全部权限点；员工状态改为「已离职」、退出组织、账号停用无法登录；

成功后返回列表页并刷新，该员工从「离职流程中的员工」移入「已离职员工」；确认离职不可撤销。

**离职管理 · 修改离职日期弹窗**

行内点「修改离职日期」打开弹窗：显示原预计离职日期，选择新日期（必填，不可早于今天）保存；

保存后预计离职日期更新，交接的完成期限跟随新日期；列表页自动刷新。

**离职管理 · 撤销离职**

行内点「撤销离职」弹出二次确认弹窗；仅「待离职」状态（申请中 / 交接中 / 待确认）的员工可撤销，执行后恢复为正常在职状态；

撤销后其离职审批与离职交接流程作废，员工从「离职流程中的员工」列表移出；撤销操作留痕。

**离职管理 · 类型配置固定分类**

「审批类型」→「类型配置」中新增固定分类「人事」，系统内置，不可改名、删除、复制；分类下增加「离职审批」入口，点击进入后只配置离职申请的表单与审批节点；

「离职审批」入口只配离职申请这一条流程：表单可按 OA 审批的表单设计方式增删字段、调整控件；默认字段：预计离职日期（日期选择，必填）、离职原因（多行文本，必填）、离职类型（单选，必填）、备注（单行文本，选填）；

审批节点支持添加节点，节点处理人可配置，默认为发起人的上级；离职交接不做表单配置，类型配置里没有它的入口；

分类与「离职审批」入口不可改名、删除、复制；本期仅 qt 品牌测试门店可见。

**员工档案 · 状态列**

web「人事」→「员工档案」列表新增「状态」列，展示当前员工状态；状态取值：在职、待离职、已离职，与离职审批流程联动；

状态变化时机：离职申请审批通过变「待离职」，HR 确认离职变「已离职」，撤销离职恢复「在职」，手动办理后直接「已离职」；

状态列只读，不提供手工修改入口；

员工档案查询区新增状态筛选（下拉：全部 / 在职 / 待离职 / 已离职），按钮「查询」「重置」。

**附：待确认与已知说明**

「办理离职」的审批离职方式是否允许 HR 代员工发起；当前「离职审批」需求写的是员工本人发起；

修改离职日期后，是否重新通知各交接项接收人；

审批节点是否支持按节点设置字段的只读 / 可编辑 / 隐藏权限；本期默认审批节点全部只读，仅发起人可填写；

本期仅 qt 品牌测试门店开放，按门店写死控制，不做权限点控制；后续全量开放需补权限点与门店配置；

手动办理离职不经审批、不做交接；快速删除本期不做；

离职管理参照钉钉智能人事离职管理设计，仅借鉴流程阶段与信息架构，不复刻钉钉文案、视觉与品牌；

离职审批与离职管理是同一条离职流程的两端：发起、审批、交接见「离职审批」需求，HR 确认与档案联动见本需求。
