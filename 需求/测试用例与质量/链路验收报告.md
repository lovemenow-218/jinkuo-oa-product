## 三、跳过 / 预期失败明细

### 2 个 Skipped（条件不具备，非功能失败）

| 用例 | 位置 | 跳过原因 |
|---|---|---|
| 员工账号不能修改履约配置应 403 | `chain_setup.py:482` | 手上两个账号都是 `sy-org-admin`，构造不出「普通员工被拒」场景，需普通员工账号才能硬化 |

### 2 个 XFAIL（已知缺陷，`strict=False` 监控，修复后自动 XPASS）

| 缺陷 | 用例 | 现象 |
|---|---|---|
| **缺陷 26** | `chain_setup.TestUnitsConfig::test_单位名含控制字符_400` | 单位名称**不过滤控制字符**——「箱\x00\x01」被 200 接受并原样入库。对照结算账户名称有「不允许控制字符」校验，说明平台有该能力，units 模块漏了 |
| **缺陷 27** | `chain_setup.TestUnitChangeReason::test_GET应提供可回填的当前变更原因` | GET 顶层无 remarks / changeReason / currentReason 任一字段，前端打开弹窗无法回填上次填的变更原因 |

## 四、本次补齐的缺口：申购价初始化

### 机制澄清（探针 + 前端反查，2026-11-02）

验收方案中「配置有效货物机构/物料/标价价格；无价格记录不能使用」**不是**一张独立的价格主数据表：

- 候选价格主数据接口（`procurement_prices` / `goods_prices` / `warehouse_prices` / `price_records` / `price_init` …）**全部 404**；
- 唯一的「价格」相关接口是 `warehouse_inquiries`（询价/询定价），但那是「生成采购协议」用的，不是申购单价门禁；
- **申购单的价格记录来自「申购协议」**：协议 `items` 里挂了 `goodsProfileId + unitPrice`（即价格记录）。「无价格记录不能使用」= 申购单行项的物料必须落在所引协议范围内，否则建单被拦（400「…不在协议中」）。

### 专项用例（`tests/web/test_warehouse_price_init.py`，marker `price_init`，5 条全过）

| 用例 | 验证点 | 结果 |
|---|---|---|
| `test_协议可配置物料与标价` | 协议 items 带回单价（价格记录存在、为正） | ✅ |
| `test_协议内物料可建申购单` | 协议内物料可正常建单（基线） | ✅ |
| `test_协议外物料被拦_无价格记录不能使用` | 协议外物料建单 400「不在协议中」 | ✅ |
| `test_报错指向实际协议外物料名` | 报错点名实际违规物料（名称/档案号），非泛化错误 | ✅ |
| `test_停用协议不可被申购单引用` | 停用协议被引用 400「协议已停用或不属于所选供货方」 | ✅ |

> 清理方式：统一走 `warehouse_document_action` + `action=void`，类级 fixture 在 teardown 回收，测试环境零遗留。
