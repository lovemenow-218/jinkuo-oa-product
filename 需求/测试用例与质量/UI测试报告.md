### 7. 入库/发货/签收负向与差异闭环（5 条，2026-11-03 下午新增）

| 场景 | UI 层实际表现（断言锚点） |
| --- | --- |
| **发货数量超限**（可发3填99） | 前端行级拦截：弹窗内出现「**本次发货不能超过订单剩余可发数量**」，**0 网络请求**、无 toast、无 `.el-form-item__error` 红字，不落库 |
| **差异签收缺原因**（合格1短少1，不填说明） | 表单红字「**请填写差异原因**」+ 0 请求 + 发货单仍待签收（对应接口层 400 语义） |

## 二、测试过程发现并修复的框架问题

1. **登录复选框**：必须点 `.el-checkbox__inner` 方框；点文字会命中《隐私条款》`<a target=_blank>` 链接，勾选不生效 → 永远停在登录页。可靠信号：`localStorage.cacheLoginPrivacy === "on"`。
2. **fixture 依赖顺序**：`ui_page` 必须依赖 `ui_session`（用例文件按字母序执行，chain/nav 先于 smoke，不挂登录 fixture 就全挂在 /login）。
3. **自定义模态检测**：提交审核/驳回/撤回/确认付款等弹的是**自定义模态**，`.el-dialog:visible` 检测不到，必须按按钮文案找。

## 三、UI 交互层的行为发现（对手工测试有价值）

1. **「先填原因再确认，不填就静默不发请求」是普遍模式**：撤回审核、驳回、审核计划三处都是"必填原因框，不填点确认 = 无 toast、无网络请求、无任何反馈"。手工测试容易误判为"按钮坏了"。
2. **数量输入框错位坑**：申购单/发货/签收的明细行有多个数字输入框（合格实收/短少/破损/拒收），自动化按"最后一个输入框"填会把拒收数填成发货量、合格实收归零、库存不增。按列语义定位，不能按位置猜。
3. **关联协议下拉依赖供货机构**：不先选供货机构时下拉为空（无任何提示）。
4. **付款凭证上传必填**：不传凭证点确定同样被静默拦下。
5. **新增发货按钮状态门禁**：未付款时 disabled——付款状态与发货入口的联动在 UI 层正确。
6. **超限拦截是"行级提示"不是表单红字**（2026-11-03 下午）：发货/入库数量超限时没有 toast、没有 `.el-form-item__error`，提示写在弹窗正文里（「本次发货不能超过订单剩余可发数量」）。断言要查弹窗 innerText，不能只查红字类。
7. **差异处理入口按诉求变化**（2026-11-03 下午）：差异待处理时配送签收页签按钮从 [新增发货/签收/撤销发货/申请退回…] 变为 [**确认补发**/更正签收/申请退回…]；「确认补发」弹 message-box（处理说明+取消/确定），按钮文案是「确定」不是「确认」。

以上均已锁进用例断言或写进用例注释。
