本文件是设计效果稿，不是交付规格。落地需前端仓库实现，且落地前须先在真机校准单位体系：本仓 Playwright 实测 H5 的 window.innerWidth=980（设备视口 402），uni-app 的 rpxCalcMaxDeviceWidth=960 会触发回落、运行时将 root font-size 设为 16px， 本稿全部 px 规格与设计 px 可能不在同一坐标系。断点一律以「弹窗内容区宽度」判定，不以视口宽度判定。

长值处理规则

  • 科目值 10021002_银行存款 一律 overflow-wrap:anywhere，在 402 视口下单行可容下；更窄或更长时允许折行，不截断、不加省略号。
  • 科目值里若含下划线，折行点可能落在下划线后，需在真机复核断行位置是否可接受。
  • 若接口实际把科目拆成「编码 + 目录名」两个字段返回，可改为两行呈现，卡片高度 +24px；本稿按单字段实现。
  • 项目名称、科目、备注三类文本均不截断；容器随内容增高。

边界处理

  • 金额为 0 显示 ¥0.00；空值或非数值显示 —，绝不显示 ¥0.00。
  • 科目缺失时字段名保留、值显示 —。
  • 备注为空时整行留空，不写「—」占位。
  • 金额超过 12 字符时，标签与数值上下分行，字号不变，不加省略号、不横向滚动。
  • 明细超过 8 条时滚动出首条后吸顶一条 ≤28px 纯文字汇总（无底色块、无下划线、不加粗），回到顶部淡出。
  • 0 条时显示「暂无费用科目明细」，且不显示「共 0 项 · 合计 ¥0.00」。

这轮要接受的代价

1）Web 端本轮不动 → 双端金额格式与空值口径会不一致（Web 仍是全角 ￥+原始值、空值显示「历史未记录」），需产品签字接受，或后续补 Web 改造。
2）卡片是弹窗内首次出现的容器分组语言，需与下方纯虚线键值行靠统一 label 色与虚线收口。
3）本方向是四个候选里 Web 改造量最大的一档，若后续决定改 Web，需同步做卡片组件与视觉回归。
4）历史单据的「当前目录」取自实时科目字典而非当年快照，字典改名或停用后目录名会变，与「与审批人当年提交一致」冲突 —— 需后端补快照或约定显示 —。
