原型要点说明

A · 消息首页：顶部为姓氏首字头像「陈」+ 用户名「陈嘉言」+ 右上铃铛（99+），不加页面标题、不显示环境提示条；仅把底部 Tab「首页」改名「消息」，「待办 / 工作台 / 我的」保持原样。列表按品牌分组，门店角标 = 该门店未读消息数（数值与排序沿用归档旧版首页演示数据，≤99 显真实数、≥100 封顶「99+」，读后下降），分组头「共 X 条消息」= 该品牌下所有门店角标之和；铃铛 = 全站未读总数按同一封顶规则显示，三处同一口径。点门店 → 进 C。搜索框做模糊/关键字匹配。门店行字号：店名 16px / 消息时间 12.5px、品牌分组头 15px；时间行只显示时间戳、不带「最近」前缀。
数字核对：41 家门店角标合计 1207（辰色酒馆首店角标「99+」按封顶前真实值 156 计）= 8 个品牌合计 418 / 370 / 133 / 107 / 52 / 48 / 48 / 31 = 汇总弹窗标题「共 1207 条消息」；铃铛按「≥100 封顶 99+」显示 99+，即 1207 的封顶形态。分组顺序按品牌合计降序、组内按角标降序、同数按最新消息时间倒序，数量与顺序全部取自归档旧版首页原型，不另行编造。C/D 的「全部10 / 未读5」是单门店消息页的独立演示数据（列表仅取 10 条），与 A 屏全量计数不同层级。
B · 消息汇总弹窗：在完整首页上点铃铛浮出，弹窗位于铃铛下方；标题「消息汇总」+ 全站消息总数；列表顺序与首页分组完全一致（按品牌合计降序，不再另排一套），固定高度内滚动（8 个真实品牌 + 5 个无消息占位品牌，共 13 行演示 20+ 品牌滚动；占位行显示 0，不计入总数）；仅展示不可点，点外部关闭。
C · 门店消息页：顶部不出现「通知」二字，门店名直接占用原标题位（沿用通知页加粗标题格式，长名单行省略）；右上保留「批量已读」；下方「全部10 / 未读5」胶囊（选中蓝底），数字为当前筛选下的条数。列表按当前门店单独取数（示例 10 条全部 / 5 条未读，可滚动），承载站内既有六类通知混排：@我的（蓝 @）/ 审批通过（绿 ✓）/ 审批驳回（红 ✕）/ 抄送我的（灰 抄）/ 待我审批（紫 审）/ 还款预警（警，蓝·橙·红·灰四态；含「还款完成」子通知）。卡片样式、主文案、类型图标与点击落点一律沿用《消息通知优化（h5）》《web 消息通知》《备用金还款预警通知》及总纲既有口径，本次不改动、不重新定义；卡片上无行内按钮，已还款卡片转灰；仅还款预警类展示金额 / 状态标签 / 还款日三行信息区。左侧方形图标、标题（未读加粗）、时间与右上未读红点为六类共用外观。C 是「消息」Tab 下的子页：保留返回箭头（点返回回到 A 门店列表），不显示底部 Tab——避免子页里底部仍高亮「消息」造成层级歧义，同时让列表多出约 50px 的可见空间。
D · 单门店用户消息页：进 App「消息」直接是该门店消息页，无品牌/门店列表、顶部不显示铃铛、无返回箭头；顶部显示该门店名，列表样式与 C 一致、按该门店取数（示例为另一门店的通知数据，体现门店间消息隔离）。D 是「消息」Tab 的根页（无上级页），必须保留底部 Tab，否则用户没有任何路径切到「待办 / 工作台 / 我的」。
已读联动：C/D 内消息标记已读（逐条点开或批量已读）后，A 对应门店角标、品牌合计、铃铛汇总数字实时同步下降，无需返回首页刷新。
搜索：仅在 A 消息首页提供，做模糊/关键字匹配（品牌名、门店名、括号内地名、数字、后缀、空格分词均可命中）；C/D 门店消息页内不提供搜索。

真实名称与品牌归属依据

名称来源：A 屏的品牌名与门店名取自 7 张「选择商户」截图实读，共 8 个品牌 / 41 家门店，全量排入列表用于验证长名称、中英混排与同名项的显示效果；仅作内部评审，外发或作通用示例前需换回虚构名。门店角标、分组头合计、门店消息时间均为归档旧版首页的演示值，按同一口径互相核对并逐项可验算，人名（陈嘉言等）为虚构。
归属判定：门店标签里同一名称作为前缀重复出现即归为一个品牌 —— 辰色酒馆 8 / 群众青年 12 / 金阔 6 / 拾叁唐 4 / 青春九厂 3 / 热辣摇滚 3 / 梦星南 3 / 第三极 2（合计 41）。「品牌」标签里的系统代号（JK / QT / UD …）未与门店名直接对应，故分组头使用真实品牌名而非代号。
名称形态：含括号地名、公司全称（最长 19 字「福州晋安区金阔管理咨询合伙企业」）、中英混排（Livehouse / Live Show）、后缀「供应链 / 美食 /（新）/【小卖部】」，以及同名不同角色的两条「金阔公司」。所有品牌与门店共用同一个平台 logo，门店无独立 logo；分组头图形本期统一使用按品牌名自动生成的两字占位，不加载任何图片；不借用平台 logo 或其他品牌图造成误认。正式品牌 logo 待提供后按品牌逐个替换（8 个品牌全部待替换）。
排版验证：门店名 16px / 600 单行省略、时间行 12.5px 只显示时间戳，分组头门店数与实际行数一致；41 家门店在 402 pt 基准下 0 行触发省略，最长 19 字公司全称可完整单行显示。逐台切换 25 种形态校验：横向溢出 0、时间行 0 换行、角标（含 99+ 三字符）与箭头不撑破行；更窄形态下长名称按方案 C 既定口径单行省略，不折行。

屏幕规格与多机型兼容

设计基准：iPhone 16 Pro，逻辑分辨率 402 × 874 pt（物理 1206 × 2622 @3x，1 pt = 1 CSS px），屏幕圆角 53 pt，灵动岛 126 × 37 pt（距屏顶 11 pt），顶部安全区 62 pt、底部安全区 34 pt（Home Indicator 134 × 5 pt，距底 8 pt）。画框内部所有字号、间距、控件尺寸均按 pt 1:1 标注，开发可直接取值。新增 iPhone 18 Pro：逻辑分辨率与安全区与 16 Pro 完全相同（402 × 874 pt · 62 / 34 pt），仅灵动岛开孔宽度由 126 pt 缩为 82 pt（高 37 pt 不变），因此页面布局无需任何调整；该宽度由供应链开孔尺寸（20.76 → 13.49 mm）按 460 ppi @3x 换算，Apple 官方未公布像素级参数。
兼容范围：切换器按 6 类共 25 种形态分组 —— 苹果直板（16 / 18 Pro、16 / 18 Pro Max、iPhone 16、iPhone Air、14 刘海、SE 3）、安卓直板（360 dp 基准、Pixel 9、Mate 80）、双折叠（Mate X7 / Z Fold 8 的外屏与展开内屏）、三折叠（Mate XT / XTs 单屏、双屏、三屏态）、阔折叠（Pura X 外屏 1:1 方形 / 展开、Pura X Max 展开、Pura X View）、竖折小折叠（Z Flip 8 外屏 / 内屏）。逻辑尺寸按 iOS pt ≈ Android dp ≈ 鸿蒙 vp 取 1:1，切换后四屏同步改变画框尺寸、安全区与挖孔形态。
适配规则：① 顶部 / 底部间距一律取系统安全区 env(safe-area-inset-*)，不写死机型常量，灵动岛、刘海、挖孔由系统自动让位，内容不进入挖孔区；② 页面为弹性三段式 —— 状态栏与底部 Tab / Home 区固定，中间列表 flex:1 内部滚动，高度随屏幕伸缩；③ 字号与间距固定 pt、不随屏宽等比缩放，避免大屏字变小、小屏挤成一团；④ 门店名单行省略、消息角标宽度自适应，326 pt 起的窄屏下仍不换行、不溢出；⑤ 铃铛「消息汇总」弹窗锚定铃铛底部（top: calc(安全区 + 52pt)），不写死绝对坐标，状态栏高度变化时始终贴合；⑥ 底部 Tab 固定在 Home Indicator 之上，手势区不承载任何点击；⑦ 弹窗列表固定高内滚，并统一设 max-height: 屏高 − 安全区 − 76pt 兜底，任何机型都不会超出屏底；⑧ 宽屏内容列约束：屏宽 > 520 pt（双折 / 三折 / 阔折展开态）时，页面内容列居中并限宽 520 pt，避免门店名与右侧角标被拉到相隔大半屏，铃铛弹窗跟随内容列右缘（right: calc(留白 + 12pt)）而非屏幕右缘；⑨ 小方形外屏降级：屏高 ≤ 500 pt（Pura X 外屏 326 × 326、Z Flip 8 外屏 330 × 300）时，弹窗由贴铃铛改为贴底半屏（限高 56%、列表内滚），门店行 / 分组头 / 搜索框切为紧凑间距，保证仍可见数条门店。
分级适配口径：≥ 375 pt 为完整适配（含 375 × 667 小屏）；屏高 ≤ 500 pt（Pura X 外屏 326 × 326、Z Flip 8 外屏 330 × 300）触发小屏降级，仍可完整操作；326 ~ 374 pt 但高度足够的形态（如 Mate XTs 单屏 350 × 776）仍走标准布局；屏宽 > 520 pt 触发宽屏限宽；< 326 pt 不作本项目验收范围。原「最小适配宽度 375 pt」已被真实折叠外屏打破，按本分级口径执行。
实测验证：逐台切换 25 种形态校验，横向溢出全为 0、底部 Tab 全在屏内、门店名 0 溢出、时间行不换行；标准与宽屏形态下弹窗距铃铛恒定 7 pt、右缘跟随内容列，小屏降级形态下弹窗贴底 10 pt 且列表内滚。据此修复了 2 处小方形外屏弹窗超底（原超出 57 / 83 pt）与 4 处展开态内容列被拉伸（原文字区宽 639 ~ 1034 pt，现统一收敛到 ≤ 444 pt）的问题。
